## Request deadlines, cancellation and errors

The SDK supports Go 1.23 or later. Configure the client once, reuse it across
requests, and release its idle connections when finished:

```go
package example

import (
    "context"
    "time"
    reacon "github.com/reacon-io/reacon-go/v2"
)

func ReadCounts(ctx context.Context, apiKey string) (*reacon.DomainCounts, error) {
    configuration := reacon.NewConfiguration()
    configuration.RequestTimeout = 30 * time.Second
    client := reacon.NewAPIClient(configuration)
    defer client.CloseIdleConnections()

    ctx = context.WithValue(ctx, reacon.ContextAPIKeys, map[string]reacon.APIKey{
        "ApiKey": {Key: apiKey},
    })
    ctx = reacon.WithRequestTimeout(ctx, 5*time.Second)
    counts, _, err := client.DomainsAPI.GetDomainCounts(ctx, "example.com").Execute()
    return counts, err
}
```

`Configuration.RequestTimeout` bounds the entire network request, including
waiting for a pool slot and reading the body. Zero uses the 30-second default;
negative values are invalid. `WithRequestTimeout` supplies a positive per-call
override. An earlier deadline or cancellation on the parent context wins.
Cancellation remains detectable with `errors.Is(err, context.Canceled)`;
timeouts match `context.DeadlineExceeded` and can also be inspected through
`*RequestTimeoutError`. Caller cancellation causes remain available through
`errors.Is`. These limits do not change the streaming helper's idle/total limits.

The SDK disables redirects and automatic request replay. This includes Go's
transparent replay of a GET after a reused connection fails: some Reacon GETs
spend credits. The standard transport retains pooling for healthy connections,
uses HTTP/1, and blocks a second connection from sending the same request. A
blocked replay is a `*TransportError` matching `ErrRequestReplayBlocked`.
A timeout, cancellation or lost response does not prove the server rejected
the operation; do not blindly retry billable or mutating operations.

A supplied `http.Client` is copied. Its standard `*http.Transport` is cloned,
preserving TLS verification, custom CA trust, proxies and connection limits.
The SDK owns the clone's pool, leaving the caller's original pool unchanged.
`CloseIdleConnections` releases only that owned pool. A custom `RoundTripper`
stays caller-owned and must honor context cancellation and avoid internal
retries. Configure clients before starting concurrent requests; do not mutate
configuration or transport settings while calls are in progress.

HTTP failures retain the generated `*http.Response` return value and expose
`*GenericOpenAPIError`: `StatusCode()`, `Headers()`, `RequestID()`, flat/nested
`Code()`, raw `Body()`, and parsed `Model()` (a generic JSON value or original
text). Undocumented, malformed and non-JSON error bodies remain inspectable.
Credit details and `Retry-After` remain in the body/headers without triggering
a retry. The returned response body remains readable after an API error.

Connection failures use `*TransportError` with the underlying cause available
through `errors.Unwrap`. A successful response with malformed JSON, an invalid
model or an unexpected media type uses `*ResponseDecodeError`, retaining status,
headers and body. Use `errors.As` to inspect these typed errors.

## Documentation For Authorization


Authentication schemes defined for the API:
### ApiKey

- **Type**: API key
- **API key parameter name**: X-API-Key
- **Location**: HTTP header

Note, each API key must be added to a map of `map[string]APIKey` where the key is: ApiKey and passed in as the auth context for each request.

Example

```go
auth := context.WithValue(
		context.Background(),
		reacon.ContextAPIKeys,
		map[string]reacon.APIKey{
			"ApiKey": {Key: "API_KEY_STRING"},
		},
	)
r, err := client.Service.Operation(auth, args)
```

### McpIdentityToken

- **Type**: HTTP Bearer token authentication

Example

```go
auth := context.WithValue(context.Background(), reacon.ContextAccessToken, "BEARER_TOKEN_STRING")
r, err := client.Service.Operation(auth, args)
```

## Retrying requests

A timeout or dropped connection does not prove that the server rejected a request. Before retrying a write or credit-consuming operation, check its outcome. Only retry when the operation is safe to repeat; when present, respect the Retry-After response header. Keep application-level retries bounded as well: wrapping an SDK call in an unbounded retry loop can multiply requests and repeat side effects.

## Reporting failures

When reporting a failure, include the SDK package version and HTTP status. Include a request identifier if the response supplies one. Remove API keys and customer data from logs and bug reports. Redact Authorization and X-API-Key headers before sharing a request. Never include the API key in a URL or a screenshot.
